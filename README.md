# Nanum CSV Viewer

대용량 CSV 파일을 **빠르게 열고** 부드럽게 탐색하는 Windows 데스크톱 뷰어입니다.
1 GB가 넘는 CSV도 첫 페이지가 즉시 표시되며, 한글 인코딩(EUC-KR / CP949 / UTF-8)을 정확히 처리합니다.

> .NET 10 · Windows Forms · 단일 실행 파일(.exe) 배포 지원

### Unreleased — 분석 스킬 팩·관리형 Python 분석 환경

- **분석 스킬 팩 20개** — 임상 연구 7(PK/PD·NCA, 임상 보고서, 연구용 의사결정 지원 문서화, 실험 설계, 검정력, scikit-survival, 분석법 검증) · 일반 통계 9(탐색적 분석, 통계 분석, statsmodels, aeon 시계열, 과학 시각화, matplotlib, seaborn, polars, dask) · 기계학습 3(scikit-learn, SHAP, UMAP) · 앱 전용 1(`nanum-python-analysis`). 19개는 [K-Dense-AI/scientific-agent-skills](https://github.com/K-Dense-AI/scientific-agent-skills) v2.72.0(MIT)을 원본 그대로 가져온 것이고, 앱 전용 1개는 이 앱이 작성했습니다. 네트워크·GPU·업로드·환자 개별 판단이 필요한 26개는 검토 후 제외했습니다.
- **로드 조건·토큰 비용** — **로컬 Python이 켜져 있고 마스터 스위치가 켜져 있을 때만** 실립니다(Python이 꺼져 있으면 0 토큰). 설정 ▸ AI 에이전트 ▸ '분석 스킬'에서 전체·분류별·스킬별로 끌 수 있고, 스킬마다 토큰 추정과 총합(전체 켬 약 550 토큰)이 보입니다. 선택을 바꾸면 같은 대화로 에이전트가 다시 시작합니다. 앱 전용 스킬은 팩이 켜져 있는 한 항상 함께 로드됩니다.
- **앱 도구 먼저** — 앱의 검증된 도구(`csv.column_stats`·`csv.quality_scan`·`csv.run_analysis`·`ws.*`)와 사용자가 메뉴에서 실행하는 분석(t검정·ANOVA·카이제곱·상관·정규성·반복측정·혼합모형·비모수·KM/Cox·ML·PCA/LDA)이 먼저입니다. Python 스킬은 앱에 없는 분석(PK/NCA, Bland-Altman, 검정력, 경쟁위험, 시계열, SHAP, 출판용 그림, 대용량 처리 등)이나 사용자가 Python을 명시했을 때만 쓰고, 어느 길을 썼는지 답에 밝힙니다.
- **표기·재현성** — Python 결과에는 **'Python 분석 (앱 검증 범위 밖)'** 표기와 재현성 머리말(원본 파일·사용/제외 행 수·필터·패키지 버전·시드·시각·사용한 스킬), 가정·수렴·다중 검정에 대한 정직한 보고가 붙습니다. 연구·집계 분석용이며 환자 개별 진단·치료용이 아닙니다.
- **관리형 Python 환경** — 설정 ▸ AI ▸ Python 환경에서 `%LOCALAPPDATA%\NanumCsvViewer\python-analysis`에 독립 venv(시스템 Python 변경 없음, system-site-packages 없음)를 만들고 묶음별로 설치·업데이트·제거합니다. 묶음은 core(pandas·numpy·scipy·statsmodels·matplotlib·seaborn·pyarrow·openpyxl) · stats(pingouin·scikit-posthocs·polars·dask·aeon) · clinical(lifelines·scikit-survival·pydoe) · ml(scikit-learn·xgboost·lightgbm·shap·imbalanced-learn·umap-learn)이며 모두 `==` 버전 고정, `--only-binary=:all:`(미리 빌드된 wheel만, 소스 빌드 없음)로 설치합니다. 설치 뒤 import를 확인하고 `requirements.lock`을 기록합니다. **64비트 Intel/AMD Windows의 Python 3.10~3.13**만 지원하며 ARM64·32비트는 거절합니다. scikit-survival은 Python 3.13에서 의존 패키지에 wheel이 없어 **3.13 미만에서만** 설치됩니다(aeon은 3.10에서 1.3, 3.11 이상에서 1.6). 환경이 있으면 에이전트의 Python이 이 환경이 됩니다.
- **`py.ensure_packages` (승인 필요)** — 에이전트는 스스로 `pip install` 하지 않고, 필요한 묶음을 이 도구로 요청합니다. 앱이 사용자 승인(승인 모드를 따름)을 받은 뒤 관리형 환경에만 설치합니다.
- **도구 ▸ Python 분석 재현 패키지 내보내기…** — 분석 스크립트·보고서·그림·`requirements.lock`·README를 폴더 또는 zip으로 묶습니다. **데이터는 기본으로 제외**됩니다.
- **'요약만' + Python 경고** — '요약만' 데이터 정책에서도 Python 스크립트는 파일을 읽어 출력할 수 있으므로 설정에 경고가 표시됩니다. 출력 정책은 스킬·가이드의 지시(안내)일 뿐 하드 보장이 아닙니다.

### v3.1.1 — 스크롤 끊김 개선

- **스크롤 끊김 개선** — 메인 그리드에 이중 버퍼링을 켰습니다. 30열·30만 행 파일에서 휠 한 단계(3행) 그리기가 약 20 ms(60 fps 한 프레임 16.7 ms 초과) → 약 4 ms, 페이지 단위 이동이 약 150 ms → 약 21 ms로 줄었습니다.

### v3.1.0 — 작업 공간별 에이전트: 대화 이어 가기, 작업 공간 설정, 메모, 뷰 출처

- **작업 공간 파일 v2** — `.ncvws`가 `version: 2`가 되고 `agent` 섹션(대화 연결·승인 모드·데이터 정책·로컬 Python 허용·메모)이 생겼습니다. 뷰마다 `createdBy`(`user` / `agent` / `wizard:join·append·compare·group`)·`createdUtc`, 에이전트 뷰는 `request`(그 턴의 사용자 메시지, 500자까지)도 기록합니다. v1 파일은 그대로 열립니다(에이전트 섹션·출처 없음). v1만 아는 앱은 v2 파일을 "더 새로운 버전이 만든 파일"로 거부합니다.
- **작업 공간별 대화** — 작업 공간을 저장하면 지금 대화(omp 세션 id + .jsonl 경로)가 파일에 연결됩니다(세션 파일이 디스크에 있을 때만 — 아직 메시지가 없는 대화는 저장하지 않음). 작업 공간 파일을 열면 그 대화를 이어 가고(omp `--resume`, 파일이 옮겨졌으면 `~/.omp/agent/sessions/*`에서 id로 찾음, 채팅 기록 다시 불러옴) 안내가 표시됩니다. 저장된 대화가 없어졌으면(예: 다른 PC에서 온 파일) 새 대화로 시작하고 채팅에 경고가 표시됩니다. 작업 공간을 바꾸면 대화도 바뀌고 omp가 그 작업 공간의 대화·분석 폴더로 다시 시작합니다. 작업 공간 ▸ **이 작업 공간의 새 대화 시작**(작업 공간 파일이 열려 있을 때만; 확인 후 저장 시 연결 교체, 이전 대화는 omp 세션 목록에 남음). 작업 공간 파일이 없으면 예전처럼 매번 새 대화입니다. 대화 연결도 작업 공간 내용이므로 바뀌면 "수정됨"으로 보고 닫기·전환 때 저장을 묻습니다.
- **작업 공간별 에이전트 설정** — 승인 모드·데이터 공유 정책·로컬 Python 허용을 작업 공간에 저장합니다. **보안 규칙: 실제 값은 앱 설정과 작업 공간 값 중 더 엄격한 쪽**이며, 받은 작업 공간 파일은 조일 수만 있고 풀 수 없습니다(승인: 항상 묻기 > 편집 자동 승인 > 모두 허용, 데이터: 요약만 > 요청마다 승인 > 허용, 로컬 Python: 끔 > 켬). omp 추가 인자(`--yolo`·`--auto-approve`·`--approval-mode`)의 고정이 승인 모드에서는 여전히 우선합니다. 보기 ▸ AI 에이전트 설정…은 작업 공간 파일이 열려 있으면 맨 위에 "설정 적용 대상"(이 작업 공간(기본) / 앱 기본값(모든 작업 공간))을 고르게 하고, 더 엄격한 값이 이겨 적용되지 않은 항목은 확인 후 메시지로 알립니다. omp 경로·추가 인자·행 상한은 계속 앱 전체 설정입니다. 채팅 창 아래 승인 드롭다운을 바꿀 때도 작업 공간이 열려 있으면 "이 작업 공간 / 앱 기본값 / 취소"를 묻습니다. 작업 공간이 실제로 무언가를 조이면 승인 선택 옆에 **🔒 작업 공간** 표시가 나타나고(툴팁에 제한 내용), 제한이 생길 때 안내가 채팅에 올라옵니다.

#### 편집 기능 (기본은 보기 전용)

- **셀 편집** — 툴바 `✎ 셀`(또는 편집 ▸ 셀 편집…, F2): 선택한 셀 하나를 대화상자에서 고치면 **바로 보기 모드로 돌아옵니다**.
- **시트 편집 모드** — 툴바 `✎ 시트`(Ctrl+Shift+E): 켜 두는 동안 여러 셀을 인라인 편집(더블클릭·F2, Enter 확정, Esc 취소)하고 아래 시트 전용 기능을 쓸 수 있습니다. 다시 눌러 끄면 보기 모드이며, 제목 표시줄과 버튼으로 현재 모드를 알 수 있습니다. 셀 편집(단일 셀 대화상자)에서는 붙여넣기·행 삽입/삭제·이름 변경이 **거부**됩니다.
  - **되돌리기/다시 실행** — `Ctrl+Z` / `Ctrl+Y`(편집 메뉴에도 있음). 셀 하나의 커밋, 붙여넣기 한 번, 지우기 한 번, 행 삽입/삭제 한 번, 컬럼 이름 변경 한 번, 모두 버리기가 각각 **한 단계**입니다(이력은 최근 500단계·200만 변경까지).
  - **블록 붙여넣기** — `Ctrl+V`: 엑셀·표 계산기 복사본(탭 = 열, 줄바꿈 = 행, 따옴표 셀 속 줄바꿈 포함)을 선택한 셀부터 붙여넣습니다. 셀 하나를 복사해 여러 셀을 선택했으면 선택 전체를 채웁니다. 블록이 표를 벗어나면 **아무것도 붙여넣지 않고** 안내합니다. `Delete`는 선택한 셀을 비웁니다. 100셀을 넘으면 확인을 받습니다.
  - **컬럼 이름 변경** — 헤더를 더블클릭(또는 편집 ▸ 컬럼 이름 변경…). 새 이름은 필터·차트·통계 대화상자에 바로 쓰이고 저장 파일의 첫 줄에 기록됩니다. 비우거나 다른 컬럼과 같은 이름은 거부합니다. 옛 이름을 쓴 표현식 필터는 계속 동작하되 칩에 ⚠가 붙습니다.
  - **행 삽입/삭제** — 편집 ▸ 위/아래에 행 삽입, 선택한 행 삭제(우클릭 메뉴에도 있음). 추가한 행은 초록색이며, 행 번호는 편집한 표 기준으로 다시 매겨집니다. 저장 파일은 삭제한 행을 건너뛰고 추가한 행을 그 위치에 같은 줄바꿈으로 씁니다.
  - **컬럼 삽입/삭제** — 편집 ▸ 컬럼 삽입…(이름, 위치 = 현재 컬럼 앞·뒤·맨 왼쪽·맨 오른쪽, 선택적으로 모든 행에 같은 값) / 컬럼 삭제, 헤더 우클릭 메뉴에도 있습니다. 삽입은 컬럼 추가와 위치 지정이 **한 단계**라 `Ctrl+Z` 한 번으로 사라집니다. **삭제는 원본 컬럼도 가능**하고 원본 파일은 그대로입니다: 삭제한 컬럼은 그리드·필터·정렬·통계·내보내기·에이전트에서 사라지고(뒤 컬럼 번호가 당겨짐) 저장 파일(CSV·xlsx)에서 빠지며, `Ctrl+Z` 한 번으로 값·이름 변경과 함께 복원됩니다. 마지막 남은 컬럼은 지울 수 없습니다. 삭제한 컬럼을 가리키던 정렬·컬럼 필터는 정리되고, 컬럼 위치로 만든 "셀 값" 필터는 해제됩니다(표현식 필터는 새 헤더로 다시 컴파일).
  - **컬럼 이동** — 시트 편집 모드에서 **헤더를 좌우로 끌어다 놓으면** 컬럼이 그 자리로 옮겨집니다(놓을 경계가 굵은 선으로 표시되고 `Esc`로 취소, 필터 깔때기·폭 조절 경계는 제외). 편집 ▸ 컬럼 왼쪽/오른쪽으로 이동과 헤더 우클릭 메뉴도 있으며 숨긴 컬럼은 건너뜁니다. 이동 한 번 = **한 단계**. 표시 순서는 그리드·필터·정렬·분석·차트·에이전트·저장 파일(CSV·xlsx)·복구 저널에 모두 같게 적용되고, 정렬 키·컬럼 필터·숨김·타입 지정은 옮긴 컬럼을 따라가며 컬럼 폭도 유지됩니다. 원본 파일은 그대로입니다.
- **편집하면 바로 반영** — 필터·정렬이 켜져 있으면 편집이 멈춘 뒤(약 0.4초) **현재 데이터로 다시 계산**하고(보던 행을 유지, 조건에서 벗어난 행은 숨겨지며 안내), 타입 배지·패싯을 갱신합니다. 이미 열려 있는 고급 통계 결과·차트 창은 결과를 몰래 바꾸지 않고, 맨 위에 **"이 창을 만든 뒤 데이터가 편집되었습니다 — 분석을 다시 실행하세요"** 안내를 붙이고 제목에 ⚠를 붙입니다. 데이터 품질 발견 목록은 비우고 다시 검사하도록 안내합니다.
- **원본은 바뀌지 않습니다** — 편집은 메모리에 쌓이고(편집한 셀은 앰버색), **편집 ▸ 편집 내용 저장…**으로 *새 파일*에 저장합니다. 편집 안 한 행은 원본 바이트 그대로 복사하고, 저장하지 않은 편집이 있으면 파일을 닫거나 바꿀 때 확인합니다.
  - **엑셀 원본(.xlsx/.xlsm/.xls)** 은 기본이 **.xlsx 저장**입니다(해당 시트 하나, 모든 값을 텍스트로 기록해 `007`·긴 숫자가 그대로이며 엑셀이 "텍스트로 저장된 숫자" 표시를 띄울 수 있음). 엑셀의 행(1,048,576)·열(16,384)·셀 글자 수(32,767) 한도를 넘으면 부분 파일 없이 거부하고 CSV 저장을 권합니다. 서식·수식·다른 시트는 가져오지 않으므로 저장되지 않습니다.
  - **SAS·SPSS·SQLite 원본**은 **CSV로 저장**되며, 저장 전에 대화상자가 "값은 텍스트로 기록되고 변수 라벨·값 라벨·선언 타입은 유지되지 않는다"고 알려 줍니다.
  - **저장 전 복구 저널** — 저장하지 않은 편집(셀·이름·삭제/추가 행)을 편집 후 약 1.5초 뒤 `%LOCALAPPDATA%\NanumCsvViewer\edits\`에 기록합니다. 앱이 비정상 종료돼도 같은 파일(경로·크기·수정 시각이 같을 때)을 다시 열면 **복구할지 묻고**, 저장·버리기를 하면 저널을 지웁니다. 원본이 바뀌었으면 복구하지 않습니다(60일 지난 저널은 자동 정리).
- **숫자 변환 없음** — 입력값은 문자열 그대로 보관·저장되어 `001`의 선행 0이 사라지지 않습니다(엑셀로 CSV를 다시 열 때 엑셀이 0을 지우는 것은 엑셀의 동작이며, 앱은 값을 바꾸지 않습니다).

- **기준선 스냅샷과 비교**(데이터 품질 메뉴) — 이전에 내보낸 품질 보고서 JSON과 현재 프로파일을 비교해 행 수·컬럼 추가/삭제·타입 변경·결측률(pp)·고유값 수·수치 범위·위장결측 후보·발견 신규/해소/지속을 보여 줍니다. 한쪽이 부분 스캔이면 근사로 표기하고, 규칙·키·참조처럼 사용자가 실행하는 검사가 현재 세션에 없으면 "해소"가 아니라 **재검사 안 됨**으로 구분합니다. Markdown/JSON으로 내보낼 수 있습니다.
- **참조 무결성 검사**(데이터 품질 메뉴) — 현재 파일의 (복합)키 값이 다른 시트 또는 다른 파일의 부모 키에 있는지 전수 검사합니다. 고아 행은 발견 패널에서 필터 칩·행 이동으로 이어지며, 빈 키는 기본으로 제외하고 건수를 따로 표시합니다. 부모 키 집합이 메모리 예산을 넘으면 부분 결과 없이 중단합니다.

### v1.15.1 — 대용량 피벗·필터 안정성 개선

- 피벗은 현재 뷰를 순차적으로 읽으며 전체 행을 집계합니다. 표는 행·열 페이지로 탐색하고, 차트는 현재 표 페이지의 범위를 표시합니다. 합계는 페이지에 관계없이 전체 집계 범위 기준입니다.
- 집계·합계 계산은 백그라운드에서 실행하며 취소할 수 있습니다. 예상 집계 메모리가 예산을 넘으면 필터·날짜 그룹·차원 축소를 안내하고 이전 결과를 유지합니다.
- 헤더 필터 후보는 200개씩 표시하며 검색·선택 상태를 페이지 간 유지합니다. 후보 목록의 메모리 예산을 넘는 컬럼은 전체 행에 적용되는 텍스트·값 목록 필터를 사용합니다.
- 패싯 분포는 백그라운드에서 계산하며 사용한 표본 범위를 표시합니다.
- 일반 분석·차트 데이터 수집도 백그라운드에서 수행합니다. 완전한 스냅샷의 메모리 예산을 넘으면 행 필터 후 재시도하도록 안내하며, 일부 행만 분석한 결과를 내놓지 않습니다.
- 카이제곱 검정은 관측된 조합만 저장해 큰 카테고리 교차표를 처리하며, 기대빈도가 작은 경우 근사 p값 해석을 제한합니다.
- 원인·검증 결과·후속 점검 항목: [안정성 점검 기록](docs/HIGH_CARDINALITY_STABILITY.md).

## ✨ 주요 기능

- **대용량 즉시 열람** — 파일 전체를 메모리에 적재하지 않고, 바이트 오프셋 인덱스 + `DataGridView` 가상 모드로 보이는 행만 그때그때 읽습니다. 1 GB 파일도 첫 페이지가 1초 안에 뜹니다.
- **분석 스킬 팩·관리형 Python 환경** — 로컬 Python을 켜면 에이전트가 번들 분석 스킬 20개(임상 7·통계 9·기계학습 3·앱 1)를 쓰고, 앱이 만든 독립 venv에 고정 버전 패키지를 설치합니다. 도구 ▸ Python 분석 재현 패키지 내보내기…로 스크립트·보고서를 묶어 냅니다.
- **백그라운드 인덱싱 + 진행 표시** — 첫 페이지를 보여주면서 나머지를 백그라운드로 인덱싱하고, 하단 상태바에 **진행바 + %** 를 표시합니다. 완료되면 "준비 완료"와 함께 필터/정렬이 활성화됩니다. 인덱서는 **벡터화 바이트 스캔(`SearchValues`)** 과 **읽기·스캔 겹치기(더블 버퍼링)** 로 동작해, 일반 NVMe에서 인덱싱 처리량이 **~2 GB/s**에 이릅니다.
- **한글 인코딩 자동 감지 + 수동 전환** — BOM 확인 → strict UTF-8 검증 → 실패 시 CP949(EUC-KR) 폴백. 상태바 우측의 인코딩 표시(신호등 왼쪽)를 클릭하거나 View ▸ 인코딩 메뉴로 즉시 바꿔 다시 디코딩할 수 있습니다(재인덱싱 불필요).
- **적응형 메모리** — RAM 예산(기본 1.5 GB) 이내면 원본 바이트를 메모리에 보관해 필터/정렬이 빠르고, 초과하면 자동으로 디스크 스캔 모드로 전환해 메모리를 일정하게 유지합니다.
- **검색 / 필터 / 정렬** — 스트리밍 "Find Next", 컬럼별/전체 필터, 컬럼 헤더 클릭 정렬. **헤더 Shift+클릭으로 다중 컬럼 정렬**(우선순위 표시)을 지원하며, 같은 값끼리는 원본 순서를 유지하는 **안정 정렬**입니다.
- **한눈에 보는 상태바** — 좌측에 **행 수 · 파일 용량**, 우측에 인코딩 위젯과 상태 표시등을 표시합니다.
- **조건 누적 필터(AND)** — 텍스트 필터에 더해, 선택한 셀의 값으로 즉시 필터를 거는 **`Filter by Cell`** 버튼/우클릭 메뉴를 제공합니다. 여러 조건이 **AND로 누적**되어 Excel처럼 점점 좁혀 볼 수 있습니다. 조건을 추가할 때는 전체가 아니라 **현재 결과만 다시 거르므로**(증분 필터) 2중·3중으로 갈수록 빨라집니다.
- **상태 표시등(신호등)** — 상태바 우측 끝의 색 점으로 상태를 한눈에: ⚪ 대기 · 🟡 불러오는 중 · 🟠 작업 중 · 🟢 준비 완료.
- **원본 행번호** — 행 헤더에 원본 파일 기준 행번호를 표시합니다. 필터·정렬해도 원래 위치를 추적할 수 있고, 헤더 폭은 드래그로 조절할 수 있습니다.

### ✨ v1.8.0 신규 — 타입 인식 필터링·패싯 분석

- **컬럼 타입 확장** — 기존 `INT/FLT/DATE/BOOL/CAT/STR`에 더해 **`DateTime`·`Time`·`Identifier`**를 자동 추론합니다. `2024-01-01 14:30`은 DateTime, `14:30:00`은 Time으로 구분하고, `yyyyMMdd` 컴팩트 날짜는 헤더와 무관하게 날짜로 인식합니다(연도 1900~2100 가드). **식별자**(선행 0 숫자·`id`/`번호`/`코드` 헤더)는 수량이 아니므로 평균 등 무의미한 수치 통계를 자동 억제합니다.
- **전 타입 헤더 필터** — `Empty`를 제외한 모든 컬럼에 타입별 필터를 제공합니다: 숫자·시간계열은 **범위(min~max, 시각 정밀도 인식)**, 범주·불리언은 **체크박스**, 문자열·식별자는 **텍스트 술어**(포함·일치·시작·끝·정규식·빈값·목록 붙여넣기). 고유값이 적은 숫자 컬럼은 범위 대신 체크박스로 폴백합니다.
- **활성 필터 칩 바** — 모든 활성 조건을 그리드 위 칩으로 표시하고, 각 칩의 **✕로 개별 제거**·**클릭으로 재편집**합니다. 조건이 둘 이상이면 **모두(AND)/하나라도(OR) 결합 토글**을 제공하며, 결합 방식은 저장된 뷰에 함께 저장됩니다. 중첩 부울 `(A AND B) OR C`는 고급 식 필터로 표현할 수 있습니다.
- **패싯 분석 패널(F6)** — 우측 패널에서 컬럼별 분포를 한눈에: 숫자는 히스토그램, 그 외는 상위 값 빈도를 가로 막대로 표시합니다. 막대를 클릭하면 그 구간/값으로 즉시 필터되고, 필터가 바뀌면 분포가 다시 계산됩니다(**크로스필터링**).

- **조건부 서식** — 보기 ▸ 조건부 서식…(또는 셀 우클릭): 규칙은 "조건(고급 필터 식: 정규식·NOT·`*` 포함) → 셀(지정한 컬럼) 또는 행 전체에 배경색·글자색·굵게" 또는 "숫자 컬럼 색상 눈금(2색/3색, 최소·최대는 현재 보기 기준으로 한 번 계산)"입니다. 목록 순서가 우선순위이며 **배경·글자색·굵게를 각각 처음 맞은 규칙이 정합니다**(위/아래 버튼으로 순서 변경, 체크로 켜고 끔, 편집 중 앞 10,000행의 일치 수 미리보기). 편집한 셀(앰버)·추가 컬럼 값(파랑)·삽입 행(초록) 강조가 규칙의 **배경보다 우선**하고 규칙의 글자색·굵게는 유지됩니다. 보이는 행만 계산하고(행 단위 캐시, 편집·필터 때 무효화) 정규식이 250ms를 넘긴 행은 "일치하지 않음"으로 세어 상태 표시줄에 알립니다. 규칙은 컬럼 **이름**으로 컬럼을 가리키며 파일별 저장 뷰(`%LOCALAPPDATA%\NanumCsvViewer\views`)에 자동 저장되어 다시 열면 적용됩니다(컬럼을 삭제·이름 변경하면 그 규칙은 적용되지 않고 관리 창에 표시). 에이전트도 같은 규칙을 만들고 지울 수 있습니다.

- ALGLIB 배포본을 `ExternalLibs/ALGLIB/`에 풀어 둡니다(`ExternalLibs/ALGLIB/alglib-csharp/lib-csharp-core/src/*.cs`를 `NanumCsvViewer.Alglib` 프로젝트가 컴파일). 라이선스상 소스를 공개 배포할 수 없어 이 폴더는 `.gitignore` 대상이며, 없으면 빌드가 안내 메시지와 함께 실패합니다. 게시(단일 exe)에는 컴파일된 ALGLIB가 포함되어 추가 파일이 없습니다.

```bash
# 빌드
dotnet build -c Release

# 실행
dotnet run --project NanumCsvViewer -c Release

# 테스트(CSV 파서·인덱서·인코딩 감지 등 단위/통합 테스트)
dotnet test
```

## 📦 단일 실행 파일 만들기

릴리즈는 **Portable**과 **Install** 두 가지로 배포합니다(둘 다 프레임워크 의존 — 앱에 .NET 미포함).

| 산출물 | 형태 | 요구사항 |
|---|---|---|
| **Portable** | `…-portable.exe` — 설치 없이 실행하는 단일 exe | [.NET 10 Desktop Runtime (x64)](https://dotnet.microsoft.com/download/dotnet/10.0) (없으면 Windows가 안내) |
| **Install** | `…-setup.exe` — 시작 메뉴 등록·제거 지원 설치 관리자 | 설치 중 .NET 10을 점검해 **없으면 자동 설치** |

앱 빌드는 `win-x64-framework` 게시 프로필을 사용하고, 설치 관리자는 `installer/NanumCsvViewer.iss`(Inno Setup)로 만듭니다.
(.NET을 포함한 자체 포함본이 필요하면 `win-x64-singlefile` 프로필로 별도 게시할 수 있습니다.)

### 릴리즈 + 코드 서명

`scripts/release.ps1`이 게시 → **앱 exe 서명** → Portable 복사 → 설치 관리자 컴파일 → **setup 서명** → **설치된 exe 서명 검증**(임시 무인 설치·제거) → GitHub 릴리즈까지 수행합니다.

- 기본적으로 **x64·arm64 두 아키텍처를 모두** 빌드·서명하고 한 릴리즈에 함께 업로드합니다. 한쪽만 만들려면 `-Arch x64` 또는 `-Arch arm64`.
- Portable·setup·**설치되는 앱 exe** 모두 SafeNet 토큰의 EV 인증서로 서명·타임스탬프됩니다. (페이로드를 먼저 서명한 뒤 패키징하므로, Inno Setup이 바이트 보존하여 설치된 exe의 서명이 유지됩니다.)

- 서명 시 토큰 PIN 프롬프트가 뜹니다(연속 서명은 SafeNet single-logon 권장). 동일 버전 재실행 시 기존 릴리즈에 자산을 덮어씁니다.

## 📖 사용법

1. **File ▸ Open**(또는 툴바 Open)으로 `.csv` / `.txt` 파일을 엽니다.
2. 하단 진행바가 끝나면(또는 진행 중에도) 자유롭게 스크롤합니다.
3. **인코딩**: 상태바 우측(신호등 왼쪽)의 인코딩 표시를 클릭해 바꿉니다(자동 감지가 틀린 경우). View ▸ 인코딩 메뉴로도 가능합니다.
4. **Find**: 검색어 입력 후 Enter → 다음 일치로 이동.
5. **Filter**: 컬럼 선택 + 검색어 → Apply. 셀을 선택한 뒤 **`Filter by Cell`**(또는 우클릭 ▸ "이 셀 값으로 필터")로 그 값 조건을 추가하면 기존 필터에 **AND로 누적**됩니다. **Clear**로 전체 해제.
6. **정렬**: 컬럼 헤더 클릭(다시 클릭 시 내림차순).
7. **상세 패널**: 시작할 때는 꺼져 있습니다(AI 패널만 켜짐). 툴바의 `행 상세 패널` 버튼, **보기 ▸ 행 상세 패널** 또는 **F4**로 켜고 끌 수 있고(폭 드래그 확장), 설정 ▸ 패널과 배치에서 시작 때 켜 둘 수 있습니다. 선택한 행 전체를 컬럼명+값으로 보여줍니다.
8. **상태 표시등**: 상태바 우측 끝 색 점으로 진행/준비 상태를 확인합니다(🟢 준비 완료).

### 정렬

- **단일 컬럼**: 컬럼 헤더 클릭(다시 클릭 시 오름↔내림 토글), 또는 `Sort ▲ / ▼` 툴바 버튼·**데이터** 메뉴(현재 셀의 열 기준). 정렬 해제는 `Ctrl+Alt+S`.
- **다중 컬럼**: 헤더를 **Shift+클릭**하면 정렬 차수가 누적됩니다(1차, 2차, 3차…). 예: `이름` 클릭 후 `나이` Shift+클릭 → 이름 오름차순, 동률이면 나이로 정렬. 활성 컬럼에는 정렬 화살표가, 다중일 때는 우선순위 번호가 헤더에 표시됩니다.
- 같은 키 값을 가진 행끼리는 **원본 파일 순서가 유지**됩니다(안정 정렬). 숫자처럼 보이는 컬럼은 수치 기준으로 정렬합니다.
- 필터 조건을 **바꾸면** 정렬이 초기화됩니다(필터를 더 좁히는 경우는 순서 유지).

### 여러 파일 작업 공간 사용법

1. 파일을 여러 개 열면 각각 탭이 됩니다. 보기 ▸ 작업 공간 탐색기(`Ctrl+Shift+W`)에서 원본·테이블·뷰를 확인합니다(시작할 때는 꺼져 있으며, 작업 공간 파일을 열면 그 파일에 저장된 배치로 복원됩니다).
2. 조인·이어 붙이기·비교·그룹 마법사로 뷰를 만들거나, 작업 공간 ▸ 새 질의(`Ctrl+Alt+Q`)에서 `SELECT`를 직접 씁니다. 한글·공백 이름은 `"…"`로 감쌉니다: `SELECT "이름" FROM "설문_명단"`.
3. 열 타입은 자동 판정된 값이고 변환 안 되는 값은 NULL입니다. 원본 텍스트가 필요하면 `"T__raw"`를 씁니다.
4. 작업이 끝나면 파일 ▸ 작업 공간 저장(`Ctrl+S`)으로 `.ncvws`에 보관합니다(데이터가 아닌 원본 경로·뷰 정의와 패널 배치). 작업 공간 메뉴에는 파일 추가·바뀐 파일 다시 읽기·마법사·메모가 있습니다.

## ⚙️ 동작 원리(요약)

핵심은 "전부 읽지 않는다"입니다.

1. 파일을 한 번 순차 스캔하며 각 레코드의 **시작 바이트 오프셋**만 인덱싱합니다.
2. 화면에 보이는 행만 오프셋으로 찾아 읽고, 선택된 인코딩으로 디코딩·파싱해 LRU 캐시에 둡니다.
3. EUC-KR/CP949/UTF-8에서는 줄바꿈·구분자·따옴표 바이트가 멀티바이트 문자 중간에 나타나지 않으므로, 바이트 단위 스캔이 인코딩과 무관하게 안전합니다(따옴표 안 줄바꿈도 정확히 처리).

## ⚠️ 제한 사항

- 엑셀(`.xlsx/.xls`)·SAS(`.sas7bdat`)·SPSS(`.sav`)·SQLite(`.db/.sqlite/.sqlite3`)는 **열 때 시트/데이터셋/테이블별 CSV로 변환**해 지원합니다(시트 탭으로 전환). 단, 바이트 오프셋 **대용량 즉시열람**은 CSV/TXT 전용입니다.
- 작업 공간: 뷰 새로 고침 시 그 탭의 필터·정렬이 초기화되고, 뷰는 읽기 전용이며, 식별자성 열은 텍스트(숫자 비교는 `CAST`), CSV 스캔은 단일 스레드(열 수가 다른 행 허용), DB 원본은 앱이 다시 가져올 때만 갱신, 포터블 exe는 DuckDB 때문에 x64 약 48 MB, 뷰가 쓰는 원본의 이름 바꾸기·제거는 거부됩니다.
- 창 위치는 컴퓨터마다 달라 `.ncvws`에 저장하지 않습니다(패널 배치만 저장).
- **UTF-16/UTF-32**는 대용량 모드에서 지원하지 않습니다(BOM 감지 시 안내).
- 매우 느린 HDD에서 디스크 모드(>약 1.5 GB)일 때 스크롤에 미세한 지연이 있을 수 있습니다.
- **분석 스킬·Python 분석(Unreleased)**: 스킬은 제3자(K-Dense) 안내문이라 에이전트가 따르는 것은 지시일 뿐 강제가 아닙니다(일부 스킬 원문의 `uv pip install`·네트워크 안내는 앱 가이드가 금지하지만 기술적으로 막지는 않습니다). 에이전트가 `csv.run_analysis`로 직접 실행하는 것은 기술통계·GLM·ANCOVA·GLzM·로지스틱뿐이고, 나머지 앱 분석은 사용자가 메뉴에서 실행해야 합니다. 스킬 선택은 앱 전체 설정이며 작업 공간 파일에는 저장되지 않습니다. 관리형 환경은 Windows 64비트 Intel/AMD(win_amd64)·Python 3.10~3.13만 지원하고(ARM64·32비트 거절), scikit-survival은 Python 3.13에서 설치되지 않습니다. '요약만' 정책 + 로컬 Python 조합은 Python 출력이 모델로 갈 수 있어 설정에 경고가 나오는데, 이는 안내일 뿐 하드 보장이 아닙니다. Python 분석 결과는 앱 검증 범위 밖입니다.
