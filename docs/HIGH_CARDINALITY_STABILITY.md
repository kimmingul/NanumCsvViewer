# 고카디널리티 안정성 점검

## 기준과 범위

사용자 요청: 카테고리가 많은 컬럼에 피벗·필터 등을 적용할 때 종료·멈춤을 해결하고 프로젝트 목표에 필요한 개선을 점검한다.
별도 GOAL 파일은 현재 작업 트리에 없으며, README의 **대용량 CSV를 빠르게 열고 부드럽게 탐색**한다는 목표를 기준으로 삼았다.
정확성·UI 응답성·메모리 증가·취소/문서 교체·범위 표시를 함께 점검한다.

피벗 표의 2만×2만 조합은 기존 차트에서 double 데이터만 약 3.2GB가 필요했다.
새 경로에서는 관측된 셀만 집계하며 표·차트의 조합 확장을 페이지 범위로 한정한다.
메모리 예산은 **프로세스 전체 RAM의 하드 제한이 아닌 집계 상태의 보수적 추정치**다. 원본 RAM 버퍼·인덱스·이전 결과·런타임 메모리는 별도다.

일반 분석과 모델리스 차트는 독립된 완전한 행 스냅샷을 사용하므로 피벗과 달리 128MiB 수집 예산을 적용한다. 큰 파일에서 이 예산을 넘으면 행 필터 후 재시도하도록 안내한다. 200만 행 고정 잘라내기는 제거했으며, 결과에는 실제 분석 범위를 표시한다. 표시할 그룹/빈도 개수 제한과 Shapiro–Wilk의 5,000개 제한은 개별 결과에 별도 표시한다.

카이제곱은 최소 기대빈도와 기대빈도 5 미만 셀 수를 희소 계산으로 함께 제공한다. 최소 기대빈도 1 미만 또는 셀의 20% 이상이 기대빈도 5 미만이면 UI에서 근사 p값·유의성 해석을 표시하지 않는다. 기준 출처: [NIST Dataplot — Chi-square independence test](https://itl.nist.gov/div898/software/dataplot/refman1/auxillar/chistest.htm). 통계량과 관측 빈도는 그대로 제공한다.

## 검증

2026-09-08, Windows x64, .NET SDK 10.0.400-preview.0.26322.102, Release.

```powershell
dotnet test NanumCsvViewer.Tests/NanumCsvViewer.Tests.csproj -c Release --no-restore --verbosity minimal
dotnet run --project bench/Bench.csproj -c Release -- cardinality <새로운-임시-CSV-경로> 2100000 512
```

벤치마크는 새 경로에만 파일을 생성하며 기존 파일을 덮어쓰지 않는다. 임시 파일 정리는 실행자가 한다.

| 실측 항목 | 결과 |
|---|---:|
| CSV 크기 | 1,128,688,919 bytes |
| 행 수 / 피벗의 행·열 카테고리 | 2,100,000 / 각각 20,000 |
| Open / 인덱싱 포함 | 25ms / 882ms |
| 희소 피벗 Count | 2020ms, 관측 셀 20,000, 합계 2,100,000 |
| 고유 ID 후보 예산 초과 처리 | 69ms |
| 마지막 행 정확 일치 필터 | 704ms, 1행 일치 |
| 실행 중 피벗 취소 | 37ms |
| 벤치 프로세스 최대 작업 집합 | 1181MiB |

이 값은 합성 데이터와 현재 장비에서의 엔진 실측이며, 모든 파일·디스크에 대한 시간 보장은 아니다.
실제 WinForms 컨트롤 회귀 테스트는 별도로 STA에서 실행한다:

- 고유 후보 10만 개에서 200개씩 표시, 마지막 후보 검색, 페이지 이동 후 체크 상태 유지.
- 행·열 카테고리 각각 2만 개에서 표 101행×42열만 생성, 마지막 페이지 접근, 전체 합계 유지.
- 중복 실행 방지 및 취소 후 이전 결과 유지.
- 8개 집계 함수 결과, 구분자 충돌, 사전 취소, 집계 예산 초과, 100만 행 단일 Count 셀의 작은 메모리 예산.
- 고유 후보 수/문자 예산·반복값 개수·취소, 필터 뷰 스냅샷의 순서 보존.
- 실제 메인 창 종료: 취소된 읽기 작업을 붙잡아 두고 문서와 창의 생존을 검증한 뒤, 마지막 읽기가 끝나야 FormClosed가 발생함을 확인.
- 일반 차트 계산을 붙잡은 동안 UI 메시지 처리가 계속됨을 확인. 연속 옵션 변경과 이전 계산 실패 뒤 최신 데이터(N=7)만 표시되는지 확인.
- 일반 분석의 수집·계산이 UI 이외 스레드에서 실행되는지, 필터된 원본 행번호(1,3)가 보존되는지, 드레인 중 패싯 재시작이 억제되는지 확인.
- 피벗의 실제 문서 읽기를 붙잡고 메인 창을 닫아, 피벗 읽기가 끝나기 전에 문서를 해제하지 않는지 확인.
- 2,000,001행 스냅샷의 마지막 행 포함, 메모리 예산·읽기 오류·취소 시 일부 행만 반환하지 않음.
- 100,000×100,000 희소 카이제곱의 관측값·통계량·64비트 자유도 및 예산, 무작위 작은 교차표 30개의 밀집 계산 기준과 비교.
- 카이제곱 기대빈도 검사도 작은 교차표의 모든 셀 계산과 비교. 고카디널리티 희소 표의 근사 신뢰도 플래그 확인.
- 중앙값·고유값 각각 32개 측정값에서 실제 2MiB/집계 예산 초과를 유발. 이전 결과·UI 조작 가능 상태가 유지되고, 입력 축소 후 12회 연속 재실행에서 값·합계 캐시·읽기 작업 목록이 정상인지 확인.
- 피벗 오류는 창 안에 표시하며 재실행 성공 시 안내가 사라지는지 확인. 새 창을 열거나 앱을 재시작하지 않아도 복구된다.
- 패싯의 이전 계산 완료 후 UI 반영을 지연시킨 채 필터를 변경하는 순서를 8회 반복. 이전 결과가 최신 필터 결과를 덮어쓰지 않음을 실제 FacetView 값으로 확인.
- 스트리밍 Max의 NaN 처리도 기존 집계 의미와 일치하도록 회귀 검증.

이번 사용자 요청 범위의 구현과 검증을 완료했다. 사용자가 제공한 실제 문제 파일은 없으므로 재현은 합성 데이터와 기존 픽스처로 수행했다. 임의의 크기·형태의 데이터에 대한 무제한 메모리/시간 보장이 아니라, 명시한 예산 내 전체 처리와 예산 초과 시 안내·복구를 보장하는 설계다.
